# 上游功能与定制 UI 整合方案

日期：2026-10-27
状态：已实施，构建与设备验证结果见 source-settings-validation-20261027.md。

## 目标与边界

延续现有主界面、玻璃效果、颜色、图标、设置弹窗框架和三分类导航。在现有设置页中补齐可见入口，允许必要的内容增补与准确文案调整。主要功能都能通过普通点击或遥控器短按找到，长按只作为快捷操作。

## 信息结构

| 页面 | 职责与内容 |
| --- | --- |
| 网络连接 | 保留路由器代理、内置代理、组播直连及代理地址；解释这些选项仅影响适用的组播流，HTTP/HLS 直连源保持其原有路径。 |
| 播放设置 | 保留三种内核、硬件解码、音频及渲染选项；将 IjkExoPlayer 正名为 UTVPlayer（基于 ExoPlayer），解码提示随内核变化，OpenSL ES 仅在 Ijk 下可用。保留现有默认内核。 |
| 频道管理 | 从上到下为节目源、M3U 管理、频道范围、扫描与导出。沿用现有控件样式和滚动容器。 |

## 频道管理页面

1. 顶部显示“节目源”选择行，例如“北京联通 IPTV ›”；普通点击打开单选列表：北京联通、北京移动、北京电信、北京三网聚合、自定义 M3U。使用一行选择器，避免把五个单选项全部塞进设置面板。明确这些是北京内置源，切换不保证在任意网络可播放。
2. 显示当前来源摘要：节目源名称、已加载频道数；自定义源显示文件名，扫描应用后显示扫描结果名称。数量不表述为已验证可播放数量。
3. 提供可见的“导入 M3U”按钮，支持选文件和粘贴内容，复用现有解析及检测能力。结果展示有效频道数、无效条目和分组，使用当前应用的设置样式与焦点效果。
4. 自定义源未准备好时，选择该项后进入导入流程；取消或检测失败时维持原来的选择。已导入时提供“查看检测结果”“重新导入”。
5. 保留“包含标清及历史频道”，仅在确实支持精选/完整两套数据的内置源下可编辑；其它来源说明按导入列表加载，避免无效开关。具体适用来源实施前核对仓库加载逻辑。
6. 提供可见的“扫描频道”“导出当前频道列表”入口。主界面已有扫描快捷入口保留；扫描页原 M3U＋CSV 导出保留。设置页导出复用统一导出实现，并明确导出的是当前列表。

## 保存与取消语义

- 设置弹窗中的节目源、内核与网络选项均先修改草稿；点击“保存并应用”才持久化并刷新。取消或返回丢弃草稿，保持当前播放。
- M3U 先读取、检测并暂存，不直接覆盖生效中的列表；成功后显示“待应用”，由外层“保存并应用”统一提交。失败、取消文件选择或取消设置均不影响当前源。
- 保存成功后才替换源并更新频道列表；保留仍存在的当前频道，无法匹配时播放新列表第一项；避免重复重载和重启播放器。
- 从设置跳往扫描页时，如有未保存修改，提示“保存并继续／放弃并继续／留在设置”；文件选择或检测弹窗返回保持草稿。
- 扫描页是独立工作流，扫描完成显示有效数量，提供“应用为节目源”“仅导出”“返回结果”。应用说明会切换当前列表，先成功保存再切换；没有有效结果时禁用应用。应用后在频道管理中可识别扫描来源，并能切回内置源。

## 快捷菜单与导航

- 长按设置、菜单键等快捷入口保留，但不再承担唯一入口职责。
- 快捷菜单的“节目源”直接进入设置的频道管理页，保持同一套选择与保存流程。
- Pad 支持点击和滚动；电视支持方向键、短按确认、返回，焦点随滚动保持可见；关闭二级弹窗后焦点回原入口。
- 新功能使用与当前设置一致的背景、字体、间距、圆角和按钮，主界面不新增运营商或上传按钮。

## 上游服务与播放改进

- 上游邻台预收、MP2 解码回退、RTP/TS 校验及起播恢复继续作为底层能力，无需增加用户开关。
- 原版自动更新和设备上报保持默认关闭。本次不增加服务开关；未来定制更新应使用自己的发布地址和安装包。

## 实施顺序与验收

1. 先补可见的节目源与 M3U 入口，统一设置草稿和保存语义，并校正内核与解码文案。
2. 再统一扫描、导出及快捷菜单路径，调整新增弹窗为当前视觉风格。
3. 对照已有截图验证主界面、频道抽屉和玻璃外观；设置页按本方案核对新增内容，不再以整个旧设置 XML 完全相同作为验收目标。
4. 回归重点：切源保存与取消、导入失败与取消、草稿跨子页面、扫描应用后恢复内置源、内核设置、遥控焦点和触屏操作。运行现有测试及构建，再在 vivo Pad 上验证完整入口链路和玻璃回归。
5. 真实 IPTV 网络、4K/MP2 与切台速度单独验收；本地夹具和界面验证不替代直播测试。
