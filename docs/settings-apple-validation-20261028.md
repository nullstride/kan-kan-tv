# 设置页优化验证方案：电视、Pad、手机

日期：2026-10-28。配套 `settings-apple-design-20261028.md`。**第一阶段原生 UI 已实现；137 项自动化单测通过。以下设备、播放和性能矩阵仍待逐项取证，不因构建成功而自动通过。**

具体执行以[详细测试与验收方案](settings-acceptance/README.md)为入口：包含确认需求映射、57条步骤/预期用例、冻结彩色示意、147条按端待执行记录和报告模板。本文件保留验证策略与历史方案检查；V/T/P/M/A/B/D旧编号用于背景追溯，正式执行使用ST编号，不能自动换算为已通过。最终深色配色与横屏要求见新方案确认基线。

## 1. 验证分层与证据

| 层 | 验证目的 | 方法/证据 | 限制 |
| --- | --- | --- | --- |
| 设计评审 | 颜色角色、分组、五种控件状态、三端布局 | 设计稿/概念示意、状态图、颜色合成计算 | HTML 示意不能证明 Android 材质性能或系统焦点 |
| 自动回归 | 草稿/保存、依赖项、布局与焦点契约 | JUnit/Robolectric；测试报告与新行为测试 | JVM/模拟窗口不能代替真实电视、IME、GPU |
| 设备 UI | 触控、键盘、遥控器、Insets 与系统辅助功能 | 真机截图、控件树、录屏、操作记录 | 一台 Pad 改分辨率只算模拟窗口 |
| 性能与播放 | 视频背景下帧时间、采样、稳定性、真实播放 | FrameMetrics/Perfetto、gfxinfo、日志、实播录屏 | 不用“收到媒体数据”替代首帧、声音与稳定播放 |

每条结果记录 APK 版本及 SHA-256、Git commit 和工作区差异标记、设备型号/Android API、物理分辨率与 density、窗口 dp、字体倍数、输入方式、主题/降级状态、测试数据、时间、证据路径和结论。未执行填“待验证”，环境不具备填“受阻+原因”。

已有 1.3.2 文档记录 133 项测试和 vivo PA2455 Pad 检查；这是旧版本基线，不能挪为本方案结果。旧记录也明确缺实体手机/电视完整验收和真实运营商环境。

## 5. 业务与草稿回归（每端主基线必测）

| ID | 步骤 | 预期 |
| --- | --- | --- |
| B01 | 修改开关/内核/连接方式/节目源→切换分类→返回 | 三端“有修改 · 待应用”；草稿一致，保存值与播放均未改变 |
| B02 | 有草稿时取消；重新打开 | 草稿丢弃，持久化配置和当前播放保持原状 |
| B03 | 有草稿时系统返回/关闭手势 | 继续编辑、放弃修改、保存并应用三个分支均正确，默认继续编辑 |
| B04 | 无修改保存/关闭；快速重复点击保存 | 不重复重建播放器、不开新检测；一次提交，按钮状态与真实结果一致 |
| B05 | 选择每种内核，核对 H.264/HEVC/OpenSL ES 依赖 | Ijk 全部适用；UTV 的 OpenSL ES 不适用；系统内核解码选项不适用；不支持项说明准确 |
| B06 | 暂存代理地址、节目源和 M3U→检测 | 采用当前草稿快照；未保存；快检不使用其他路由回退掩盖错误；结果显示本次配置 |
| B07 | 检测→取消→重新开始→旧结果延迟到达 | 旧代次不更新新页面；退出后不弹幽灵结果；取消操作可见且响应 |
| B08 | 检测时切网/断网；结果后修改配置 | 前者结果失效并提示重试；后者标为过期，不能当作新配置结果 |
| B09 | 推荐源→选择推荐→取消或保存 | 选择仅写草稿；取消保留旧源；保存后才切换。节目数量与快检收包数不表示全部可播 |
| B10 | 首次未选源→跳过→修改播放设置→保存 | 仍未选源，不自动确认联通，不自动开始播放 |
| B11 | M3U 有效/无效/超长/空内容，检测与暂存 | 错误就近显示；失败不覆盖草稿；成功暂存，保存才生效；长内容不遮固定动作 |
| B12 | 有草稿前往扫描，分别选择三个分支；执行导出 | 原有保存/放弃/留在设置语义保留；导出使用已生效列表，有明确文案 |
| B13 | 提交校验失败、存储/应用失败、离开页面后异步完成 | 不显示虚假成功；草稿保留并可重试；生命周期结束后不操作已销毁窗口 |
| B14 | 系统旋转/分屏重建/进程重建 | Activity 重建恢复必要草稿；进程死亡若不支持恢复须明确重新加载已保存设置，不能显示旧“已应用” |

B13 的失败场景用可控测试替身/本地服务触发，避免破坏正式配置。测试命名与真实行为对应，不为验证 XML 字符串写镜像测试。

## 7. 性能与稳定性门槛

以下为项目拟定门槛，不是苹果官方指标。先在同设备、同片源、同窗口与电源条件记录旧版，再测新版；至少三轮，每轮包含暖机和稳定区间。录屏会影响性能，帧数据另做不录屏的配对测量。

- 60Hz 设备：交互稳定段 UI 帧耗时 p95 ≤16.7ms、p99 ≤33.3ms；其他刷新率按帧预算折算，必须同时报告刷新率与超预算比例。低端设备如果不满足，先降级材质再复测，不能以视觉更好为由直接豁免。
- 重复同一路径 3 轮，janky-frame 比例相比基线增加不超过 2 个百分点；快速遥控器操作不持续掉帧。记录实际呈现帧，不把截图/PixelCopy 回调耗时当整体帧时间。
- 输入反馈首次可见目标 ≤100ms；取消检测后 UI 反馈 ≤200ms。网络底层释放时间另记，不将“界面已取消”当作线程已释放证明。
- 1080p/4K 背景播放下停留设置 30 分钟，覆盖 SurfaceView / TextureView；应用打开关闭设置 100 次。无崩溃/ANR、焦点丢失或持续内存增长。
- 等量 20 次开关的三个批次后，在相同空闲与 GC 观察条件下，内存不呈阶梯增长；第三批相对第一批的稳定 PSS 增量建议 ≤10MB，超出需结合 heap/bitmap 归因，不能只看单次 PSS。
- 复用现有共享视频采样，不随设置行数增长捕获次数；完全不透明设置场景额外捕获为 0，确有可见玻璃区域则按可见性与共享调度说明记录。
- 各内核至少完成短时开关设置回归；目标设备上 4K/HEVC、音频同步、切台恢复及组播/HTTP 路径需有真实环境记录。前后音画/首帧延迟无可重复的新回退；不同网络不可直接比较。

若 UI 帧数据不可采集，标记未验证，不用“肉眼流畅”替代量化门槛。若缺真实 IPTV 网络，使用本地测试片验证 UI 和渲染，再单独标真实 IPTV 播放受阻。

## 8. 自动化与运行入口

沿用 Windows 原生入口。由 Node REPL 的 `child_process.spawnSync/spawn("cmd.exe", ...)` 直接启动；不用 PowerShell。

```text
tools\aio.cmd build --isolated-network
```

该现有入口执行 `testDebugUnitTest assembleDebug`；`--isolated-network` 是项目 Gradle 验证配置，不能理解为操作系统网络隔离。设备测试可沿用 `tools/network-device-check.js`、`tools/source-settings-device-check.js`、`tools/adaptive-device-check.js`、`tools/glass-device-check.js`，执行前读取其参数/副作用并选择独立 QA 包，避免改动用户正式配置。

优先扩展的现有测试：`PhoneSettingsTest`、`AdaptiveDeviceUiTest`、`NetworkDialogUiTest`、`SourceNetworkControllerTest`、`DraftNetworkProbeTest`、`VisibleSourceSettingsTest`、`GlassForegroundTest`、`GlassCaptureGateTest`。新增有意义的状态/行为覆盖：TV 聚焦与选中分离、开关单次激活、草稿跨窗口、取消/过期回调、无变更提交和降低动态效果。

## 9. 发布门槛与记录模板

发布必须满足：三端主流程无 P0/P1；必测核心用例全部通过；自动回归零失败；实体 TV/Pad/手机的输入、字号、安全区通过；实际合成对比达标；性能门槛通过或已经实施可复验的自动降级；APK 身份/签名/版本/校验核对完成。缺实体端或运营商环境时可交付明确标识的预览版，不能称三端正式验收完成。

```text
用例：
APK / SHA-256 / Git 状态：
设备 / Android API / 分辨率 / density / 窗口 dp：
输入 / 字体倍数 / 外观 / 材质后端：
前置配置 / 测试数据与网络：
步骤与实际结果：
结论：通过 / 失败 / 待验证 / 受阻
截图 / 录屏 / 帧数据 / 日志路径：
问题级别 / 责任项 / 复验结果：
```

建议先完成可点击示意评审，再以 P0 视觉统一、P1 多端交互、P2 状态动效逐步交付；每步对照旧版本复测，避免把颜色、布局、配置持久化、播放器重启一起变更后难以定位回归。
