# 节目源检测回退修复（2026-11-02）

## 问题与修复

旧检测流程使用设置草稿创建扫描器时，禁用了连接回退。默认路由器代理不可达时，检测不会继续验证本机组播接收；只抽查首尾两个频道、每次等待 1.5 秒，也可能遗漏可用频道。

- 所选连接方式失败后，继续验证另一种连接方式：路由器代理与本机组播接收互相补测。结果保留两项连接的状态和失败原因，并说明是否依赖补测方式收到数据。
- 每个节目源最多抽查四个不同地址的频道，覆盖列表首部、中部和尾部；收到媒体数据后结束该节目源的抽查，显示实际检测数量。
- 单次连接探测等待延长至四秒。HTTP 重定向和 HLS 请求共享该连接的总预算；所有节目源并行检测，整次检测约四十秒内结束。
- 取消检测会关闭正在接收的组播 socket，避免等待接收超时。接收循环恢复数据包容量，并遵循剩余超时预算。
- 检测只读取设置草稿，不保存配置或更换节目源。不再把抽查失败表述为全部频道失效；HTTP/HLS 节目源仍直接检查媒体地址，不补测无关的组播路径。
- 此修复最初在本地开发版 1.3.3 中验证；当前开源版连同上游时移整合后为 1.3.4，versionCode 134，包名为 `com.bjunicom.iptv`。

## 验证

- `tools\aio.cmd build --isolated-network` 成功，完成完整单元测试及 APK 构建。
- 25 个测试套件、147 项测试通过，零失败、零错误、零跳过。
- 新增八项回归：草稿代理失败后的接收回退、组播失败后的代理回退、两条连接失败原因保留、主连接成功不补测、取消阻塞接收、中间频道可用与实际抽查计数、抽样去重和覆盖范围、跨 HTTP 重定向的总超时。
- 原草稿配置不写入、节目源不自动切换、HTTP/HLS 媒体检查和界面回归继续通过。
- 原修复验证已核对 APK 包名、版本与签名。开源版使用 Android 默认调试签名，Release 需自行签名；和其他本地签名安装包之间不能据此保证覆盖安装。
- 接收回退测试使用本机 HTTP/UDP 测试数据，不依赖运营商或路由器。尚未在用户的联通 Wi-Fi 和手机上完成实际收包与播放验收。

## 手机上验证

1. 安装修复版，保留现有设置，连接原先使用的联通 Wi-Fi。
2. 进入“设置 → 网络连接 → 检测节目源”，检测结束后展开“查看详情”。
3. 若路由器代理失败但补测组播收到数据，可以在高级连接设置选择“内置代理”后保存并尝试播放。
4. 若两种连接都未收到数据，继续核对所在地区、IPTV 接入和路由器转发状态。内置联通频道针对北京联通，普通联通 Wi-Fi 本身不保证能接收这些 IPTV 组播。
