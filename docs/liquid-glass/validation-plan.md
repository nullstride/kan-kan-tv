# 看看电视 · 液态玻璃验证方案

版本：1.0；日期：2026-10-26；状态：待实施。对应[开发方案](development-plan.md)，结果填写到[验证记录](validation-record.md)。本文中的目标值不是已测结果。

## 1. 验证原则与状态

分别验证视觉、输入交互、视频背景、功能、性能和旧系统兼容性。单元测试不验证 GPU 视觉；静态图片不验证视频采样；vivo 平板不能代替 Android TV；设置控件存在不代表保存与播放行为正确。

状态统一使用：未执行、通过、失败、受环境阻塞、不适用。“受环境阻塞”必须写明缺少的设备/网络/素材及替代验证范围，不能计为通过；不适用必须有具体依据。

每项证据至少包含：版本标识或源文件指纹、APK SHA-256、设备型号/API/分辨率/刷新率、渲染器与内核、素材或频道、步骤、预期、实际、截图/录像/日志链接。性能还需原始数据与基线对照。

## 2. 环境与素材矩阵

| 环境 | 重点 | 当前情况 |
| --- | --- | --- |
| vivo PA2455 / Android14 / arm64 | 主验收：AGSL、触屏、示意图、两种视频渲染、性能 | 上轮已连接验证过旧材质，实施时重新检查 |
| API33 设备或支持真实 GPU 的模拟器 | AGSL 最低版本、shader 编译、图形 API 边界 | 待确认；模拟器结果不代表实体 GPU 性能 |
| API31–32 | RenderEffect 可用而 AGSL 不可用的分支 | 待准备 |
| API24–30 | PixelCopy 与材质降级 | 待准备 |
| API21–23 | 最低安装版本、启动、无 API33 链接错误、Surface 降级 | 待准备；纯单元测试不足以完成此项 |
| Android TV / 机顶盒 + 实体遥控器 | 1080p/4K、距离可读性、焦点/长按/返回、安全边距 | 待确认；ADB 按键仅作辅助 |

素材必须同时包含：现有山湖示意图、棋盘格/细线图、接近纯白/纯黑背景、高对比字幕画面、快速运动视频、可控 HTTP 视频、可用 IPTV 流。测试资源不得冒充节目元数据，不改变生产频道库；临时 URL/测试入口放在测试代码或调试构建中。

主设备至少覆盖 SurfaceView 与 TextureView；三内核以相同可控内容逐一检查，支持的编码以既有能力为准。4K/HEVC 用合法可用素材；没有素材或解码硬件时记录阻塞，不能依靠 UI 的“4K”徽章证明播放成功。

## 3. 基线与证据准备

1. 读取 `baseline.json`，核对当前源码变化；保留已新增的设置分类及其他工作，记录新的实际基线。
2. 保存基线源码（含未跟踪文件）和 APK；记录文件哈希。旧 APK 若早于当前源码，必须标注，不能视为同一版本。
3. 对基线运行构建与原测试，保存报告；先记录已有失败或环境问题，避免把它们归于新材质。
4. 同一主设备、同一亮度/刷新率/视频/网络，记录旧版截图和性能。至少包含主控制条、频道侧栏、数字盘、设置三个分类、扫描页、失败状态。
5. 新版用相同条件复测。A/B 各预热 30 秒，每种场景测 60 秒、重复 3 次；避免充电/温控/后台下载状态不一致。

证据建议放在 `build/ui-review/liquid-glass/<版本>/<设备>/<用例>/`，文件名采用 `before.png`、`after.png`、`interaction.mp4`、`metrics.txt`、`logcat.txt`。该目录可能被忽略；正式交付时将需要保留的证据复制到独立输出目录并在验证记录中链接。不要在报告中包含真实家庭网络凭据。

## 4. 视觉与交互验收

| 编号 | 操作/素材 | 必须达到的结果 |
| --- | --- | --- |
| V01 折射 | 棋盘格和细线背景，显示单个胶囊，移动焦点/控件 | 边缘局部有可辨识的背景弯曲，中央内容相对稳定；不是全图平移、放大或单纯模糊；文字图标不变形 |
| V02 高光 | 亮/暗背景，按压并移动焦点；录制 20 秒 | 边缘明暗有方向与强弱差异；触控或焦点状态变化连续；不是整圈等亮白描边 |
| V03 透明/色散 | 山湖、白底、黑底、彩色细线 | 可见背景色和材质层次；无厚重灰板、刺眼彩虹边或红绿字幕重影；前景内容仍清楚 |
| V04 小控件动态 | 连续点按、取消按压、长按、快速左右切换 30 次 | 无闪黑、跳位、缩放裁切和残影；不重复触发点击；每次有明确终态 |
| V05 页面层级 | 主 HUD、侧栏、设置和扫描截图对照 | 玻璃集中在导航和悬浮操作；列表不形成多层厚板；没有原始 URL 占据主视觉，信息仍可访问 |
| V06 可读性/布局 | 亮字幕背景；字体 1.0/1.3 倍；平板横屏与 TV 1080p/4K | 文本不被截断或重叠；关键触控区域至少 48dp；焦点缩放不出裁剪边界；安全边距正确 |
| V07 状态语义 | 焦点移到非当前频道，切换收藏，开关 HUD/侧栏 | 当前频道、焦点、收藏三者可区分，不仅依赖颜色；浏览不被六秒计时器收起；关闭动画后操作仍正常 |

可读性使用最差亮暗背景截图检查，正文目标对比度 4.5:1，大字及必要图形目标 3:1；复杂动态背景采用局部背衬确保结果。若暂时只有人工目测，记录为人工评估，不宣称已测对比度。

必须同时提交静态对照和交互录像。上游项目截图只作参考，不能作为本项目通过证据。Apple 风格相似度允许用户主观反馈，但边缘折射、内容清晰、交互连续等客观项仍必须达到。

| T-F04 播放操作 | 循环所有画面比例；重连；查看信息、选择文字；制造加载/缓冲/最终失败 | 比例真实改变；重连执行；完整地址/轨道/速度可读；未知帧率不伪造；失败时操作可达 |
| T-F05 网络设置 | 三种模式逐一选择并保存；修改代理地址；取消未保存修改；关闭/重开应用 | 值与解析后的播放路径一致；取消不落盘；重启保持设置；测试后恢复原配置 |

| T-F09 网络恢复 | 原 StreamRecoveryTest；受控 HTTP 超时/EOF；真实组播条件下重入/回退；失败后再选另一台 | 原重试、组播包长处理和回退语义保留；一次失败不能永久禁用 udpxy；UI 不吞恢复事件 |

## 7. 性能预算与测量方法

以下是开发前的初始验收预算。不得在观察到失败后静默放宽；如确需调整，记录设备条件、实际原因与变更版本。优先降级装饰效果保证播放。

| 指标 | 初始目标 |
| --- | --- |
| UI 帧耗时 | 主设备 60Hz 交互场景争取 p95≤16.7ms；相对基线 p95 增量≤2ms，慢帧比例增量≤3个百分点 |
| 主线程采样 | 记录每次耗时，p95≤4ms；不能因玻璃引入持续长帧或 ANR |
| 视频背景时效 | 运动测试中采样至显示延迟目标≤150ms；不得肉眼明显冻结/阶梯式跳动 |
| 内存 | 同场景应用 PSS 增量目标≤25MiB；连续30分钟和反复开关100次后无持续增长趋势 |
| CPU/GPU | 同一统计口径下应用 CPU 平均占用增量目标≤10个百分点；记录 GPU/温控数据，不能把多核百分比混为整机百分比 |
| 播放影响 | 可控视频无新增可感知音画卡顿；可测视频丢帧率增量≤1个百分点；首帧延时中位数回归不超过 max(100ms, 基线10%) |
| 隐藏态 | 没有新增截图/模糊任务；CPU 回到基线波动范围 |

测量场景：静态图＋HUD、运动视频＋HUD、运动视频＋侧栏滚动、快速焦点移动、控件全隐藏、错误重连。使用 `dumpsys gfxinfo`/FrameMetrics/Perfetto 测 UI，使用播放器计数或视频轨迹测解码丢帧；gfxinfo 的 UI 帧率不能代替视频帧率。`dumpsys meminfo` 记录 PSS；图形内存或 GPU 时间不可用时明确记录缺失。

同时保留不启用高级材质的 A/B 对照。运行时若采样持续超预算，验证降采样、降低模糊或回退是否有效。静态图片应缓存，不能持续以视频频率重新生成背景。

## 8. 自动化与执行入口

沿用 `StartupSmokeTest`、`StreamRecoveryTest`、`M3uParserTest`。增量测试重点为：API能力选择、shader失败降级、异步采样过期丢弃、隐藏/暂停停采样、旧配置保存语义、遥控器环路和示意图首帧切换。纯颜色、圆角常量不写镜像式单元测试；光学效果用实机图形证据验证。

Windows 通过直接启动的 `cmd.exe` 执行，不能套在 PowerShell 中。Android 工具保持 Windows 原生侧。以下从项目根目录运行，路径按本机实际安装检查：

```bat
mkdir "%TEMP%\iptv-java"
set "JAVA_TOOL_OPTIONS=-Djava.io.tmpdir=%TEMP%/iptv-java -Djdk.net.unixdomain.tmpdir=%TEMP%/iptv-java"
gradlew.bat --no-daemon testDebugUnitTest assembleDebug
```

上述短临时目录用于本机已遇到的 JDK Unix socket 问题；目录存在时不必重复创建。复杂编排在开发阶段添加稳定 runner，不能拼长串内联 shell。

```bat
"%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe" devices -l
"%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe" -s <device-serial> install --no-streaming -r app\build\outputs\apk\debug\app-debug.apk
"%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe" -s <device-serial> shell am start -n com.kankan.iptv/.ui.MainActivity
```

将 `<device-serial>` 替换为本机已确认的设备；不要把实际编号写入版本控制。使用 `--no-streaming` 是因为本机此前流式安装出现超时；以明确 Success 和设备已安装版本核验为准。日志应落盘后短周期检查，安装未返回成功不能宣称已更新。

辅助取证命令（将 `<serial>` 替换为已确认设备）：

```text
adb -s <serial> shell dumpsys gfxinfo com.kankan.iptv reset
adb -s <serial> shell dumpsys gfxinfo com.kankan.iptv framestats
adb -s <serial> shell dumpsys meminfo com.kankan.iptv
adb -s <serial> shell screenrecord --time-limit 20 /sdcard/kankan-glass.mp4
adb -s <serial> pull /sdcard/kankan-glass.mp4 <本机证据目录>
```

截图用 `exec-out screencap -p` 的二进制输出保存，不能经文本编码转换。UI 帧统计测试前 reset 即可，不清空整机日志。录像本身会影响性能，视觉录像与性能采样分开运行。

## 9. 缺陷等级与交付判定

| 等级 | 示例 | 处理 |
| --- | --- | --- |
| P0 | 数据丢失、无法启动、破坏原播放或升级安装 | 停止扩大集成，修复或回退材质 |
| P1 | 功能入口/配置语义丢失、焦点陷阱、真实视频被示意图挡住、明显卡顿/泄漏、旧设备崩溃 | 本轮交付前必须解决 |
| P2 | 轻微外观不一致、非关键间距或细节 | 明确记录，可在预览版说明中列出 |

**预览交付**：构建/自动化通过，目标平板静态材质与核心交互通过，无 P0/P1；可以向用户交付带示意图的预览 APK，但必须列出视频、IPTV、旧系统、TV 或性能未完成项，不得称“完整验收通过”。

**完整验收**：V01–V07、T-F01–T-F11、S01–S05、C01–C03及性能预算均有适用环境的证据，P0/P1为零，许可证/依赖/版本和数据保留核验完成。受环境阻塞的必需项保持未完成；没有可用联通网络时明确不能确认 IPTV 实播及真实组播恢复。

交付报告必须区分：自动化通过数、实机实际执行项、未验证范围、剩余问题、APK位置/哈希、可恢复的上一版。用户对风格的反馈记录在视觉项中，不用“已使用开源库”代替效果验收。
