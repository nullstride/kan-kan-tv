# 看看电视 · 液态玻璃开发方案

版本：1.0；日期：2026-10-26；状态：开发前设计。本文中的新类名、参数和阶段产物均为计划，不代表已经实现。

## 1. 目标与范围

将现有“深灰渐变＋低分辨率模糊＋均匀描边”升级为具有边缘折射、方向性高光、轻微色散和连续交互反馈的玻璃材质。参考 Apple TV 的悬浮导航及观看体验，不宣称与 Apple 私有系统材质完全相同。

优先改善控制胶囊、当前焦点、频道侧栏。文字和图标保持清晰，节目画面仍是主体。设置和扫描页以可读性与功能密度为先，不给每一行重复叠加玻璃。

允许调整：UI 布局、绘制层、焦点反馈、过渡动画、触控区域、无障碍描述、图标与品牌资源；允许在播放器 UI 回调处增加绘制通知。

不在本轮重构：频道解析和存储、网络请求、组播代理、重试策略、播放器内核及解码逻辑。不得删除任何现有入口、修改应用 ID/签名或清除用户设置。不得为了材质强制切换 TextureView、降低视频分辨率或改变当前频道选择规则。不迁移 Flutter，不全量重写 Compose，不加入虚构 EPG。

## 3. 开源方案与依赖决策

| 方案 | 已检查版本 | 用途与限制 |
| --- | --- | --- |
| [QmDeve/AndroidLiquidGlassView](https://github.com/QmDeve/AndroidLiquidGlassView) | `d4238c557e46271f29ec0e3d3ee211bcf58dc2e0` | 优先原生实现；MIT；Java/View、AGSL 折射与色散、触摸/弹性 API |
| [Kyant0/AndroidLiquidGlass](https://github.com/Kyant0/AndroidLiquidGlass) | `65ab177e90e5c1d8c62e70cf7755841982da65f6` | Apache-2.0；参考 Lens、Highlight、按钮/导航样例；本轮不引入完整 Compose 栈 |
| [styropyr0/Prismal](https://github.com/styropyr0/Prismal) | `daace64c56a7044e66282ce4521995982324b1cc` | MIT；OpenGL 备选；minSdk25，多 GLSurfaceView 与采样开销尚未实测 |

QmDeve 当前源码要求 minSdk24、compileSdk37、Java21，而效果本身要求 API33。README 的 Maven 版本为 `com.qmdeve.liquidglass:core:1.1.0`，其发布包兼容性未验证，不能把 README 当成可直接接入的证明。

依赖选择顺序：

1. 检查固定发布版本的 POM/AAR、minSdk、依赖、字节码和实际 API 使用，运行最小兼容构建。
2. 只有在保留 minSdk21 和既有构建/功能兼容性时才直接依赖。不能用 `tools:overrideLibrary` 隐藏未解决的兼容错误。
3. 若发布包不兼容，采用已固定提交的必要 Java/AGSL 核心，放入隔离的内部渲染适配模块；记录来源、改动和许可证，提供 API33 以下独立降级。不得默默升级整套工具链或提高最低安装版本。
4. 无法安全隔离时，停止该路径的集成并记录具体阻塞；保留基线效果和完整功能。Prismal 仅在重新评估后启用。

引入的源码、shader、复制的示例均须保留版权与许可证。若使用 Kyant 代码，按其 Apache-2.0 文件及 NOTICE 实际内容处理；只参考外观时记录参考来源即可。依赖一律锁定版本，不使用浮动分支。新增依赖的 APK 体积和运行内存纳入验证。

## 4. 视觉与交互设计约束

| 区域 | 目标 |
| --- | --- |
| 主播放画面 | 保持全屏内容；控件隐藏时不做后台玻璃采样 |
| 顶部导航/操作胶囊 | 轻染色、局部折射、方向性高光，背景明暗可见；避免通栏厚灰块 |
| 底部控制 | 按操作组组织，玻璃集中在容器与焦点；不让六个按钮变成六块厚玻璃 |
| 频道侧栏 | 可读的薄雾玻璃面，边缘有厚度，列表行以轻背景分隔；折射不能扭曲文字 |
| 焦点 | 焦点变化伴随小幅缩放和高光响应；与“当前频道”“已收藏”始终区分 |
| 设置/扫描/信息 | 清晰稳定的表面；保存、取消、停止扫描等动作在各状态都可达 |
| Logo | 沿用“看看电视”及层叠电视/播放图形；如微调材质，同时检查启动图标和 TV banner |

首轮调参起点（非验收结果）：控制胶囊染色 alpha 0.08–0.20，侧栏 0.18–0.32；局部可用文字背衬提升可读性。折射带宽建议取控件短边的 8%–18%，小胶囊先限制到 3–8dp；位移从 2–6dp 试起。上游 setter 的单位必须核实，统一由 dp 转成 shader 像素；不得直接套用 Demo 的强折射/彩虹边。

控制胶囊和侧栏可使用不同模糊等级；色散保持微弱，亮底和棋盘格下不出现明显红绿重影。焦点缩放约 1.03–1.06，过渡约 160–220ms；按压反馈应连续且可取消。系统关闭动画时直接更新终态。材质动画不承担点击判定，不抢占 RecyclerView 滚动、长按收藏或原播放器手势。

## 5. 接入架构

拟将当前 `VideoGlass` 的采样与绘制职责拆开，命名可随代码风格调整：

- `BackdropFrameSource`：统一输出画面、源位置、尺寸、裁剪映射、时间戳和代次。
- `GlassRenderer`：统一的绑定、更新、绘制、释放接口。
- `AgslGlassRenderer`：API33+ 使用开源折射 shader；只处理背景，文字图标另层绘制。
- `FallbackGlassRenderer`：低版本/采样失败/性能降级时绘制当前可读材质。
- `GlassController`：管理面板注册、共享采样、显示状态、能力判断与资源释放。

预览图 / SurfaceView / TextureView → 共享背景帧 → 坐标映射与裁剪 → 模糊和折射 → 高光 → 清晰控件内容。

QmDeve 的 `LiquidGlassimpl.record()` 使用 `target.draw(rec)`，无法直接取得独立 SurfaceView 视频层。需把视频帧提供给受控采样源或适配 shader 的输入，不直接 `bind(ijkVideoView)` 后假设完成。避免采集包含玻璃自身的窗口，防止递归叠影。

### 5.1 三类背景

| 背景 | 采样与更新 |
| --- | --- |
| 静态示意图 | 按 centerCrop 的实际映射采样；图片、尺寸、位置变化才更新；保留“画面预览 · 非直播”标记 |
| SurfaceView | 有效 Surface 上使用 PixelCopy；处理未创建、无数据、销毁和错误回调；不改变播放器渲染方式 |
| TextureView | 仅在 available 时采样；限制读回频率；记录主线程取图耗时，不能阻塞交互 |

每个可见场景共享一次采样，不为每个按钮单独截图。所有回调带播放代次与生命周期标记，切台、切换 Surface/Texture、配置变化或销毁后丢弃过期帧。正确处理黑边、16:9/4:3、铺满裁剪、侧栏动画位置和屏幕旋转；不得把旧频道像素留在新频道玻璃里。

### 5.2 性能与生命周期

旧实现的 900ms/160px 只适合静态或弱模糊，不能直接宣称能支撑新动态折射。首轮实验以共享长边约 640px、可见视频背景约 15fps 为起点，根据真机测量调整；采样与交互动画解耦，不能每次按压都分配截图。

限制同时在途采样为 1；shader、RenderEffect、路径与缓冲尽可能复用。Bitmap 采用明确的读写所有权，不能回收仍被 HWUI 引用的对象。采样失败可短暂保留同代有效帧，持续失败则退回可读表面；切台后不能保留上一代帧。

HUD/侧栏全部隐藏或 Activity 暂停时停采样，销毁时释放线程、监听和 GPU 资源。降低采样率、分辨率或关闭折射的降级顺序由实际测量决定；只降低装饰效果，不降低播放质量。提供内部强制降级开关用于 A/B 验证与排错，不把 shader 参数放进普通用户设置。

### 5.3 系统兼容策略

| Android | 计划行为 |
| --- | --- |
| API21–23 | 可读的半透明降级；SurfaceView 不走 PixelCopy；不得加载 API33 专用实现 |
| API24–30 | 可选受控采样与旧材质；不执行 AGSL |
| API31–32 | 可利用兼容的 GPU 模糊；折射仍降级 |
| API33+ | 在硬件加速、shader 和背景源可用时启用完整折射；异常切回降级 |

高级效果是可选能力，不是安装和播放前提。API33 类隔离加载；验证最低版本不存在类验证/链接错误。Robolectric 通过不能替代设备 GPU 验证。

## 8. 文件边界、风险和回退

主要改动范围：`ui/VideoGlass.java` 或拆分后的材质类，`MainActivity` 的材质绑定/生命周期，必要的 XML/Drawable/Color/主题资源、许可证和 UI 回归测试。设置页的新分类布局属于必须保留的已有工作。`player/`、`network/`、`repository/`、配置存储原则上只读；若发现必须改动，先记录具体原因及新增回归范围。

| 风险 | 处理 |
| --- | --- |
| 依赖抬高系统或工具链门槛 | 发布包核验；优先隔离核心适配，不静默提高 minSdk |
| 视频采不到或坐标错 | 三类源独立验证；不能拿静态图通过代替视频通过 |
| 高光/折射过强、阅读困难 | 小控件先行；使用同背景对照与可读性验收 |
| GPU/采样导致卡顿发热 | A/B 测量、共享采样、预算降级；播放质量优先 |
| 焦点/手势被新 View 拦截 | 保留事件处理入口；遥控器全环路与触摸冲突回归 |
| 已有未提交/其他对话修改被覆盖 | 使用指纹比对与源码备份，按当前文件增量实现 |

回退分两层：运行时通过独立降级实现恢复可读 UI；开发回退只撤销本轮材质增量，保留此前 UI、设置分类和网络恢复修复。出现崩溃、播放回归、入口丢失或无法控制的帧耗时时必须回退高级效果。交付物含固定依赖信息、许可证、测试记录、截图/录像、性能数据和 APK SHA-256。
