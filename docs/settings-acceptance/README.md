## 1. 确认基线：开发时不得丢失的细节

### 1.1 颜色与状态

以下为本项目 sRGB 深色基线，采用苹果设计原则，不是苹果官方固定色卡。三端相同语义，预览宿主/系统浅色模式不得意外覆盖；本轮不要求新增浅色主题。

| 角色 | 冻结值 | 验收说明 |
| --- | --- | --- |
| 内容底 / 分组 / 抬升表面 | #111113 / #1C1C1E / #2C2C2E | 内容稳定不透明，导航/操作栏允许克制高光 |
| 主文字 / 说明文字 | #F5F5F7 / #B8B8C0 | 说明不是可随意降低透明度的装饰 |
| 非交互细分隔 | #3B3B40 | 以最终彩色示意覆盖早期 #424247；不承担必要输入边界/焦点识别 |
| 链接与选中图标 | #80B8FF | 少量使用，不能整页蓝灰化 |
| 开启 / 成功 | #30D158 | 另有滑块位置、勾或文字，不仅靠绿色 |
| 待应用 | #FFD60A | 圆点 + “有修改 · 待应用” |
| 错误 | #FF6961 | 图标、原因及重试/修正入口 |
| 保存可用 | #F5F5F7 底 / #1D1D1F 字 | 有草稿才启用，提交中防重复 |
| 保存不可用 | #303034 底 / #A0A0A8 字 | 无草稿，视觉及事件均不可激活 |
| 检测普通 / 检测中 | #24364F / #BCD8FF；#253B57 / #C5DDFF | 每组为底/字；真实任务状态驱动 |
| 检测成功 | #183D26 底 / #96EFAD 字 | 成功含义与真实检测能力一致 |
| 已选分类 | #353538 基底 + 轻高光 | 当前分类有图标/字重等证据 |
| TV 焦点 | #F5F5F7 底 / #1D1D1F 字 | 采用最终示意明亮焦点；焦点与配置选中分开 |

颜色验收分两层：资源/状态映射与上述 token 对齐；实际截图上的透明高光、按下、焦点、不可用等组合测合成对比。非交互分隔线不要求 3:1；必要控件边界和焦点要求 ≥3:1，正文及说明 ≥4.5:1，大字号标题 ≥3:1。正常模式的实体不透明表面核对 token，玻璃/高光不要求逐像素等于 token；高对比/不透明降级允许提高对比，但须记录变体。

主布局约束：手机侧栏 128–144dp、主项16–17sp/说明14sp；Pad 主项17sp、内容最大约640–720dp；TV 侧栏180–220dp、主项22–24sp/说明18–20sp、行高64–72dp，远距与真实 density 校准。手机不得因为高度 <400dp 自动套竖版；只有有效内容宽不足/大字号确实无法容纳时，才在横屏内降为分类→详情单栏。

状态契约：`clean → dirty → applying → clean`；变回初值回到 clean；应用失败回到 dirty；取消回到已保存值。检测另有 `idle → running → success/failure/timeout/cancelled`，不改变保存状态。结果关联检测代次、草稿快照和网络环境；修改草稿或切网后不能当作当前配置有效结论。

### 1.3 原型与正式实现的差异

冻结示意用于颜色角色、布局方向和局部状态外观，不是功能真值。示意检测是计时演示，不代表网络可达/可播；TV 只有局部键盘演示；CSS 像素不能当 Android dp/sp；预览窄容器重排不能当手机竖屏要求。它省略了 OpenSL ES、渲染方式、完整连接方式、M3U、扫描/导出等。演示中的草稿字段、离页取消、假检测成功、简单保存和内核依赖不得照搬为原生契约。

需求表与详细用例约束正式行为，冻结示意提供视觉参考。这里已明确统一的分隔线、选中分类和 TV 焦点值覆盖早期文档相应起始值。任何其它冲突应记录差异并更新本文件，不能静默择一实现。

每次开始从指定 F0/F1 重置；记录所有初值，单用例完成后恢复。保存/取消断言需同时检查 UI、持久化配置快照、播放器创建/释放与频道刷新计数；不能仅凭 toast 判断。异步测试记录任务代次与取消/释放事件。未有可观测入口时标受阻，实施时补最小可测试接口，不能以缺日志判通过。

层级：U=单元/Robolectric行为回归；I=原生设备自动化；M=人工真机/可访问性；F=Perfetto/帧/内存/播放测量。表中是建议组合，U不能代替M/F。用例的每个分支/取值都须执行并分别留证，不能只执行一条代表路径。

## 5. 结果记录、缺陷与发布门槛

执行账本是一用例一端一行的最低覆盖清单；同端多设备/尺寸/分支的具体执行放入每次报告。只有规定分支和必测环境全部通过，该行才能汇总为通过。CSV状态限定为：待执行、通过、失败、受阻、不适用；受阻需原因及缺少的设备/数据，不适用需可核实的平台能力原因，不能用“不适用”掩盖未开发功能。

证据命名建议 `runs/<run-id>/<device-id>/ST-xxx/<branch>-<timestamp>.*`；每个运行含APK hash、源码状态、设备API/窗口/输入/字体/后端、数据hash、前置值、逐步实际结果、原始证据路径及缺陷编号。不要把动态网络地址/凭据写入公开证据。缺陷记录需求/用例、复现率、实际/预期、影响端、日志及复验；修复后原失败记录保留，追加复验，不覆盖历史。

发布必须同时满足：

1. ST-001～057全部有结论，P0/P1无失败、无未处理受阻；三端主基线与边界矩阵完成，缺实体端不能称三端正式验收。
2. 新增及现有自动回归零失败；配置不被草稿/检测/导出误写，重复提交、失败、取消、旧回调均有副作用证据。
3. 深色颜色/组合态/实际合成对比、横屏手机/IME/安全区、TV焦点、Pad分屏、200%字与读屏通过。
4. 帧/输入/生命周期/稳定性门槛通过；低端降级须自动触发且复验通过。动效建议时长或PSS建议值偏差须有归因与复核记录，不可静默忽略；量化数据缺失不算通过。
5. 真实播放与运营商环境结果单列；只有本地片/模拟网络时明确受阻，交付只能标“预览/未完成真实IPTV验收”。APK身份、版本、签名及SHA-256核对，报告可追溯到同一构建。

本轮实现第一阶段设置页并运行自动回归；未安装 APK，也未将上述人工设备用例标记为通过。发布门槛仍以本节矩阵及逐项证据为准。
