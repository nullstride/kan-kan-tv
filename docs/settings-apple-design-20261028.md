# 设置页优化方案：苹果交互原则与黑白状态动效

日期：2026-10-28。覆盖 Android TV / 电视盒子、Android Pad、Android 手机。本文记录设计基线与实施方案；第一阶段原生设置页已实现，三端实体验收仍未完成。

实施与验收入口：[详细测试方案与确认基线](settings-acceptance/README.md)。该文件锁定最终深色配色、手机横屏与完整功能，提供57条步骤/预期用例和按端执行账本；本文保留调研与设计背景。后续开发逐项引用需求R编号和用例ST编号。

## 1. 推荐方案

采用「中性分组内容 + 克制玻璃导航 + 有意义的黑白状态变形」。沿用首页的材质语言，统一设置页的颜色、控件和反馈；电视、Pad、手机共用业务和语义颜色，分别设计布局与输入行为。

苹果风格来自信息层级、材质分工、状态反馈和输入适配。苹果官方没有一组永远不变的“苹果颜色”：语义颜色会随系统版本、外观、背景和辅助功能变化。此项目为 Android 原生 Java/View，实现的是这些原则的本地适配，不能直接获得 UIKit / SwiftUI 的系统 Liquid Glass 行为。

## 3. 现状审查

基于 `utv` 当前源码及已有 1.3.2 截图；截图是历史基线，不是本轮实机截图。

| 问题 | 源码证据 | 优化方向 |
| --- | --- | --- |
| 设置页与首页的中性玻璃风格脱节 | `bg_settings_surface.xml` 为 #222630；分类选中 #2B3C54、焦点 #35435A | 设置专属中性表面与状态 token，少量共享玻璃导航 |
| 各状态分散硬编码 | `bg_settings_save.xml`、`bg_settings_input.xml` 含独立蓝色描边和底色 | 全部指向语义颜色和 ColorStateList，覆盖 disabled/pressed/focused/selected 组合 |
| 设置仍是密集表单 | 两套 `dialog_player_settings*.xml` 使用 RadioButton / CheckBox | 设置行：标题 + 当前值 + 箭头；二值设置使用开关；选择页显示勾选 |
| 大屏设置没有独立的完整远距排版 | 共用样式主体 14sp，说明 12sp，分类宽 142dp | TV 另设尺寸资源与完整焦点图，远距实机校准 |
| 手机短窗口靠压缩字号容纳 | 手机标签/选项 13sp，说明 11sp，输入框 40dp | 优先重排和滚动；主体 16sp 起、可读说明 14sp 起，触控区域至少 48dp |

| 电视焦点与配置选择需保持分离 | `MainActivity` 使用显式分类方向键及下一焦点设置 | 分类上下只移动焦点；OK/右键进入分类，选项 OK 才变更草稿 |
| 草稿提示覆盖不均 | `tv_phone_settings_status` 目前仅手机布局具有 | 三端统一 dirty 状态与“有修改 · 待应用”提示 |

## 4. 信息架构与组件

保留用户熟悉的三个一级分类，首期不新增“外观”分类。

| 分类 | 首屏内容 | 二级/高级内容 |
| --- | --- | --- |
| 网络连接 | 当前/待应用节目源摘要；检测节目源；最近检测结论（如有） | IPTV 连接设置：连接方式选择、条件出现的代理地址；原始诊断详情折叠 |
| 播放设置 | 播放内核摘要；硬件解码与音频分组；渲染方式摘要 | 内核选择列表；H.264、HEVC、OpenSL ES 开关；SurfaceView / TextureView 选择列表 |
| 频道管理 | 节目源选择；导入 M3U；包含标清及历史频道开关 | M3U 编辑与检测、扫描频道、导出当前已生效列表 |

组件规范：

- 分组设置行：左侧标题和可换行说明；右侧当前值/开关/箭头。分组圆角 18dp，内部细分隔线，避免一行一个浮雕卡片。
- 二值项：整行有明确命名；开关与行点击只能提交一次切换；开启增加滑块位置与“已开启”读屏状态。电视整行只产生一个焦点。
- 多选一：主行显示当前值；激活后在 TV/Pad 显示可聚焦选择面板，手机窄屏进入选择页。当前值保留勾选；浏览其他行不会修改。
- 输入项：持久标签、示例、错误就近显示；不用 placeholder 代替标题。代理地址保留光标左右移动，不能用全局左键返回吞掉编辑操作。
- 当前内核不支持的设置：保留可见、显示原因、不可激活；不静默清除用户曾保存的其他内核配置。
- 图标：优先复用现有自有矢量图标，统一线宽与对齐；不因“苹果风格”直接复制受平台使用条件限制的资源。

## 5. 颜色与材质

下表是本项目建议的 sRGB 起始值，**不是苹果官方固定色值表**。默认延续深色观看体验；浅色是对比评审和后续外观支持的配对设计，不意味着本轮已增加自动主题。必要时在设计稿/QA 开关中验证配对。

| 语义 token | 深色起点 | 浅色起点 | 使用 |
| --- | --- | --- | --- |
| settings.canvas | #111113 | #F2F2F7 | 设置内容底层 |
| settings.group | #1C1C1E | #FFFFFF | 分组表面 |
| settings.raised | #2C2C2E | #E5E5EA | 输入、次级层级 |
| settings.label | #F5F5F7 | #1D1D1F | 主标签 |
| settings.secondaryLabel | #B8B8C0 | #5C5C64 | 可读说明；不用透明度代替所有层级 |
| settings.separator | #3B3B40 | #D1D1D6 | 非交互结构线；按最终彩色示意统一 |
| settings.selection | #353538 | #E5E5EA | 已选分类底色，配轻高光与图标/字重 |
| settings.action / onAction | #F5F5F7 / #1D1D1F | #1D1D1F / #FFFFFF | 唯一高强调的“保存并应用” |
| settings.link | #80B8FF | #005AC7 | 少量链接或次级可操作文字 |
| settings.positive | #30D158 | #167C36 | 开启/成功图标，配状态文字 |
| settings.warning | #FFD60A | #805500 | 提醒图标与文字 |
| settings.error | #FF6961 | #B42318 | 错误提示；辅以错误图标与原因 |
| settings.focusSurface / onFocus | #F5F5F7 / #1D1D1F | #29292C / #FFFFFF | TV 当前焦点；按最终彩色示意统一，保留选中勾与开关位置 |

高对比模式不只加粗边框：提升说明文字至接近主文字；扩大选中和未选的明度差；玻璃退为不透明底；输入边界、焦点轮廓达到可见的 3:1 目标。所有关键文字按实际合成背景测量；不能仅测 token 原值。

材质分工：

1. 手机整页设置以不透明内容为底；顶部操作栏可使用 regular 观感。Pad/TV 的设置覆盖播放画面时保留外部上下文并适度压暗。
2. 侧栏和操作栏允许更厚的 regular 风格；复杂视频背后先保证文字稳定。列表、诊断结果和编辑器使用不透明/近不透明内容表面。
3. 保持现有文字前景独立绘制，不把文字、图标放进折射采样。首页共享采样与 GlassMotion 可复用，但不要给每行设置开启 PixelCopy。
4. 不在已经被完全不透明内容遮住的区域继续视频玻璃采样。SurfaceView 背景模糊需验证真实采样，不能把 Android 窗口 dim 当作 blur。
5. API21–32、shader 失败、降低透明度或性能不足时使用稳定不透明/毛玻璃替代；阴影、高光和几何层级仍表达可操作性。

## 6. 三端布局与输入

身份与窗口能力分开：保留 `DeviceUi` 电视优先识别；手机横屏仍是手机。布局根据当前窗口宽高及 Insets 选择，Pad 分屏可以变单栏，不能因此丢失草稿。

| 端 | 布局建议 | 排版起点（Android dp/sp） | 输入与返回 |
| --- | --- | --- | --- |
| 电视 | 屏幕内约 80–88% 宽的设置层；左分类、右内容、固定底部操作。侧栏约 180–220dp；实际按 720p/1080p/4K density 校准 | 主项 22–24sp、说明 18–20sp、标题 30–32sp；行高 64–72dp；视安全区预留约 5% 起点 | 上下移动焦点，OK 激活，右键进入内容，非编辑状态左键返回分类；Back 先关子面板，再返回设置，再返回播放 |
| Pad | 足够宽时双栏，侧栏 200–240dp，内容最大约 640–720dp，正文独立滚动、保存区固定；当前窗口宽 <720dp 或内容宽不足约 440dp 时单栏 | 主项 17sp、说明 14–15sp、行高至少 56dp、触控目标至少 48dp | 触控为主；键盘 Tab/Shift+Tab 按阅读顺序，Enter/Space 激活；鼠标 hover 轻反馈，不能套用 TV 放大 |
| 手机 | **横屏为正式设计基线**，包括 640×320dp、800×360dp、840×380dp；左侧分类约 128–144dp，右侧内容独立滚动，顶部固定返回、待应用状态与保存动作。不因高度低于 400dp 改成竖版结构；极窄窗口或大字体使有效内容宽不足时，仍在横屏内使用分类→详情单栏 | 主项 16–17sp、说明 14sp、行高至少 52dp；操作区至少 48dp | 系统返回/可见返回按钮；左右挖孔与手势区独立避让。软键盘弹出优先保证输入与提交可达，正文收缩滚动；必要时临时隐藏分类栏，收键盘后恢复 |

手机维持当前横屏使用方式，主示意和正式验收均按横屏，竖屏不作为本轮设计或验收目标。极窄窗口/大字体的单栏是横屏内的适配：优先保证内容列约 360dp 的可用宽度、字号和操作尺寸；不能以常规横屏高度较低为由直接套用竖屏页面。Pad 的单栏阈值另按其当前窗口判断。

电视焦点细则：

- 正常态保持中性；选中态留勾选/值/开关；焦点态使用高明度表面、深色文字及约 1.02–1.04 倍轻抬升；按下约 0.98 倍。保证周围留白与父布局不裁切。
- 选中+焦点同时存在时，勾选和当前值仍可见；不可用态优先于按下/选中。以组合状态测试，不只看 selector 顺序。
- 打开一级设置聚焦当前分类；打开选择器定位当前值；检测期间焦点留在固定取消动作；结果更新不抢走用户正在操作的焦点。
- 返回后恢复触发项与滚动位置。关闭/折叠一个包含焦点的区域时，焦点回到其触发项；不能掉到后台播放器。

## 7. 黑白动效的具体用法

时长为本项目建议，需录屏与可用性校准；不是苹果官方数值。

| 场景 | 建议反馈 | 约束 |
| --- | --- | --- |
| 触控按下 | 容器 1→0.98，80–120ms；松开回到稳定态，140–180ms | 不拦截点击；离开、取消、滚动打断时复位 |
| 电视焦点 | 150–190ms 明度/轻缩放变化 | 快速连按使用最新目标，不能排队播放；减少动态效果时保留静态焦点 |
| 分类切换 | 120–180ms 轻淡变，方向与导航一致 | 不让大段文字跟随橡皮泥扭曲；立即可操作 |
| 检测节目源 | 固定尺寸操作区域内“检测”胶囊→进度符号+“正在检测”；结果图标变勾/提醒 | 始终保留“取消检测”，焦点对象稳定；说明真实约 25 秒上限；无真实进度不显示假百分比 |
| 保存并应用 | 同一按钮“保存并应用”→“正在应用”→“设置已应用”；180–240ms 图标/圆角过渡 | 容器占位不跳动；真实提交后才成功。开始播放另显“正在连接”，首帧后才可称播放成功 |
| 高级设置展开 | 箭头旋转+内容尺寸过渡，180–220ms | 维持滚动锚点，若裁切或大字号则直接展开；收起前处理内部焦点 |
| 开关 | 滑块平移、轨道明度/绿色变化，140–180ms | 状态逻辑立即写草稿，动画随状态显示，不能反过来在动画结束写业务 |

纯黑白适合导航、普通操作与变形主体；开启、错误、提醒可以保留少量语义色和文字。绿色开关遵循苹果常见语义；如果后续选用单色开关，必须通过位置、形状及读屏状态保证辨识。

减少动态效果/系统动画关闭：去掉缩放、弹簧、折射动态和容器变形，用静态图标与文字即时更新或≤100ms 淡变。循环加载不作为唯一进度信息，静态“正在检测”及取消动作持续可用。后台、不可见、页面关闭时停止动画与采样。

## 8. 草稿、检测与应用状态

沿用“草稿 → 保存并应用”的事务含义。开关外观即时变化的是草稿，三端显示“有修改 · 待应用”；不会因采用苹果样式就变成即时生效。

| 用户动作 | 应有行为 |
| --- | --- |
| 切换分类/打开子页 | 共用同一草稿；保留各分类滚动位置与选择 |
| 检测节目源 | 对当前草稿建立快照检测，不保存；结果标注本次使用的配置；检测中配置变化则标注结果过期 |
| 选择推荐源/M3U 检测后暂存 | 更新草稿摘要，显示待应用；不宣称已经切换播放 |
| 取消 | 放弃本轮草稿并关闭；文案可用“取消修改”明确意图 |
| 返回/关闭手势，有未保存修改 | 提供“继续编辑 / 放弃修改 / 保存并应用”，默认安全落点为继续编辑；无修改直接返回 |
| 保存并应用 | 无变化时不重建播放器；防止重复提交；失败时保留草稿并就近说明；成功后回播放器，连接状态单独反馈 |
| 从未选择节目源时保存播放设置 | 仍保持未选择，不自动确认默认联通、不自动开始播放 |
| 扫描或导出 | 扫描前继续原有未保存处理；导出明确使用已生效列表，不把草稿导出成已生效结果 |

当前保存链存在多个 setter 与频道刷新；不能仅加一个“原子成功”动画就认为有了原子事务。实施时需梳理校验、提交失败、Activity 重建与异步回调代次，保证反馈与真实状态一致。

## 9. 分步实施与改动位置

| 阶段 | 工作 | 涉及位置 | 完成条件 |
| --- | --- | --- | --- |
| P0：统一视觉 | 引入 settings 语义颜色、文字与状态资源；中性分组表面；TV 尺寸与字重；检查动态弹窗 | `values/colors.xml`（推荐另建 settings_colors.xml）、`settings_styles.xml`、`phone_settings_styles.xml`、`bg_settings_*.xml`；必要时 `values-television` 或运行时尺寸应用 | 三端所有设置与子页视觉一致，静态对比达标 |

替换 CheckBox 为 SwitchCompat 时，需要同步修改 MainActivity 的强制类型、监听、控件依赖和现有单测；不能仅替换 XML 标签。建议分离共用 SettingsDraft/状态渲染逻辑，三端只处理布局和输入；首期可小步提取，不进行整套播放器框架重构。
